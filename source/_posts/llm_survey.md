## 摘要

自从1950年代提出图灵测试以来，人类一直在探索机器对语言智能的掌握。语言本质上是一个复杂、错综复杂的人类表达系统，受语法规则的支配。开发能够理解和掌握语言的人工智能 （AI） 算法是一项重大挑战。在过去的二十年中，语言建模作为一种主要方法，在语言理解和生成方面得到了广泛的研究，从统计语言模型发展到神经语言模型。近年来，通过对大型语料库进行Transformer模型的预训练，提出了预训练语言模型（PLM），显示出强大的解决各种自然语言处理（NLP）任务的能力。由于研究人员发现模型缩放可以提高模型容量，因此他们通过将参数缩放比例增加到更大的尺寸来进一步研究缩放效应。有趣的是，当参数尺度超过一定水平时，这些放大的语言模型不仅实现了显著的性能提升，而且还表现出一些小规模语言模型（例如，BERT）所没有的特殊能力（例如，上下文学习）。为了区分不同参数尺度中的语言模型，研究界创造了术语“大型语言模型”（LLM），用于描述规模较大的PLM（例如，包含数百或数千亿个参数）。近年来，学术界和工业界对LLMs的研究得到了很大的推进，其中一项显著的进展是ChatGPT（一款基于LLMs开发的强大的AI聊天机器人）的推出，引起了社会的广泛关注。LLM 的技术发展对整个 AI 社区产生了重要影响，这将彻底改变我们开发和使用 AI 算法的方式。考虑到这种快速的技术进步，在本次调查中，我们通过介绍LLM的背景、主要发现和主流技术来回顾LLM的最新进展。具体而言，我们重点关注LLM的四个主要方面，即预训练、适应调整、利用和能力评估。此外，我们还总结了开发 LLM 的可用资源，并讨论了未来方向的剩余问题。本调查提供了对 LLM 文献的最新回顾，这对研究人员和工程师来说都是有用的资源。

## 1. **LLMs 的背景**

通常，大型语言模型（LLM）是指包含数千亿（或更多）参数的语言模型，这些参数是在大量文本数据上训练的，例如模型 GPT-3、PaLM、Galactica 和 LLaMA。具体来说，LLM 建立在 Transformer 架构之上，其中多头注意力层堆叠在一个非常深的神经网络中。现有的 LLM 主要采用与小语言模型类似的模型架构（即 Transformer）和预训练目标（即语言建模）。作为主要区别，LLM 在很大程度上扩展了模型大小、预训练数据和总计算量（扩大倍数）。他们可以更好地理解自然语言，并根据给定的上下文（例如 prompt）生成高质量的文本。这种容量改进可以用标度律进行部分地描述，其中性能大致遵循模型大小的大幅增加而增加。然而根据标度律，某些能力（例如，上下文学习）是不可预测的，只有当模型大小超过某个水平时才能观察到。为了快速了解 LLM 的工作原理，本部分介绍了 LLM 的基本背景，包括缩放定律、涌现能力和关键技术。

目前，LLM主要建立在Transformer架构[22]之上，其中多头注意力层堆叠在一个非常深的神经网络中。现有的 LLM 采用与小型语言模型类似的 Transformer 架构和预训练目标（例如，语言建模）。然而，LLM 显着扩展了模型大小、数据大小和总数。在现有文献中，由于模型容量还与数据大小和总计算量有关，因此对 LLM 的最小参数尺度没有正式共识。在本次调查中，我们对 LLM 的定义略显宽松，主要侧重于讨论模型大小大于 10B 的语言模型。 计算（放大倍率）。广泛的研究表明，缩放可以在很大程度上提高LLM的模型容量[26,55,56]。因此，建立一种定量方法来表征缩放效应是有用的。接下来，我们介绍了 Transformer 语言模型的两个代表性缩放定律 [30， 34]。

关于缩放定律的讨论。在介绍完这些公式之后，我们继续从以下两个方面讨论缩放定律，以加深对它的理解：

• 可预测的缩放。在实践中，缩放定律可用于指导LLM的训练，并且已被证明是可行的，基于较小模型的性能可靠地估计较大模型的性能，称为可预测缩放[46]。可预测的扩展对训练 LLM 的好处主要有两个方面。首先，对于大型模型，严格检查各种训练技巧或变体是不可行的，如果从小型模型中获得的经验也可以应用于大型模型，那将是非常有帮助的。例如，可以训练小型代理模型，以找到大型模型的数据混合的最佳时间表[59]。其次，大规模模型的训练时间较长，经常存在训练损失尖峰等问题，可以采用缩放定律来监控LLM的训练状态，例如及早识别异常性能。尽管缩放定律表征了性能增加（或损失减少）的平滑趋势，但它也表明，随着模型缩放，收益递减7可能会发生。OpenAI团队的一项实证研究[58]表明，即使接近收益递减点（即接近不可减少的损失）[58]，表示质量或语义内容仍然可以有效提高。这一发现表明，训练大型模型有望提高下游任务的性能。为了进一步探索缩放效应，一个潜在的问题是，用于训练 LLM 的可用数据量实际上是有限的。随着模型规模的不断扩大，LLM的公共文本数据将很快“耗尽”[60]。因此，研究缩放定律如何适用于数据受限的制度是有意义的[61]，在这种制度中，数据重复或增强可能有助于缓解数据稀缺性。

• 任务级的可预测性。现有的尺度定律研究大多是针对语言建模损失（例如，nats [30]中的每标记交叉熵损失），而在实践中，我们更关注 LLM 在实际任务中的表现。因此，一个基本问题是，语言建模损失的减少如何转化为任务绩效的提高[58]。直观地说，语言建模损失较小的模型往往在下游任务上产生更好的性能，因为语言建模损失可以被视为整体模型容量的一般度量。GPT-4 [46] 报告说，某些能力（例如编码能力）可以通过缩放定律准确预测。尽管如此，读者应该意识到，语言建模损失的直接减少并不总是意味着下游任务的模型性能有所提高。特别是，在某些任务中会出现逆缩放现象，随着语言建模损失的减少，任务性能会出人意料地变差[62]。总的来说，探索的难度更大，返回表征任务级缩放定律，因为它可能还依赖于与任务相关的信息（任务指标、任务难度等）。此外，根据缩放定律，某些能力（例如，上下文学习[55]）是不可预测的，只有当模型大小超过一定水平时才能观察到（如下所述）。LLM 的涌现能力。在文献[31]中，LLM的涌现能力被正式定义为“在小型模型中不存在但在大型模型中出现的能力”，这是LLM与以前的PLM区别开来的最突出特征之一。当出现紧急能力时，它进一步引入了一个显着的特征[31]：

• 情境学习。GPT-3 正式引入了上下文学习 （ICL） 能力 [55]：假设语言模型已经提供了自然语言指令和/或多个任务演示，它可以通过完成输入文本的单词序列来为测试实例生成预期的输出，而无需额外的训练或梯度更新。在GPT系列模型中，175B GPT-3模型总体上表现出较强的ICL能力，但GPT-1和GPT-2模型则不然。这种能力还取决于具体的下游任务。例如，ICL能力可以在13B GPT-3的算术任务（例如，3位数的加法和减法）中出现，但175B GPT-3甚至不能很好地处理波斯语QA任务[31]。

• 指令跟随。通过对通过自然语言描述格式化的多任务数据集的混合进行微调（称为指令调优），LLM在以指令形式描述的看不见的任务上表现良好[28,66,67]。通过指令调优，LLM 可以在不使用显式示例的情况下遵循新任务的任务指令，从而具有更高的泛化能力。根据[67]中的实验，当模型大小达到68B时，指令调优的LaMDA-PT [68]在看不见的任务上开始明显优于未调优的LaMDA-PT，但对于8B或更小的模型大小则不然。最近的一项研究[69]发现，PaLM至少需要62B的模型大小才能在四个评估基准（即MMLU、BBH、TyDiQA和MGSM）中的各种任务中表现良好，尽管对于某些特定任务（例如MMLU），更小的模型大小可能就足够了。

• 循序渐进的推理。对于小型语言模型，通常很难解决涉及以下方面的复杂任务多个推理步骤，例如数学单词问题。相比之下，在思维链（CoT）提示策略[33]中，LLM可以通过利用提示机制来解决此类任务，该机制涉及中间推理步骤来推导出最终答案。据推测，这种能力可能是通过代码训练获得的[33,47]。一项实证研究[33]表明，当应用于模型大小大于60B的PaLM和LaMDA变体时，CoT提示可以带来性能提升（在算术推理基准上），而当模型大小超过100B时，它相对于标准提示的优势变得更加明显。此外，对于不同的任务，CoT提示的性能改进似乎也有所不同，例如，GSM8K>MAWPS>PALM的SWAMP[33]。

**涌现能力与缩放定律的关系**。在现有文献[30,31,34]中，缩放定律和涌现能力提供了两个视角来理解大型模型相对于小型模型的优势。一般来说，缩放定律（通常通过语言建模损失来衡量）描述了可预测的绩效关系和收益递减的潜在影响，而涌现能力（通常通过任务绩效来衡量）是不可预测的，但一旦这种能力真正出现，就会非常有利可图。由于这两种观点反映了不同的绩效趋势（持续改进与急剧的绩效飞跃），因此它们可能会导致不一致的发现或观察结果。关于涌现能力的合理性也存在广泛的争论。一种流行的推测是，紧急能力可能部分归因于特殊任务的评估设置（例如，不连续的评估指标）[70,71]：当评估指标相应地改变时，紧急能力曲线的清晰度将消失。然而，LLM 在大多数任务上的性能自然会以不连续的方式被用户感知。例如，最终用户更喜欢由 LLM 生成的可靠代码，这些代码可以成功通过测试用例，但对在两个失败的代码之间选择错误较少的更好代码不太感兴趣。最近，一项研究[72]提出了一种新的评估设置，可以扩大任务指标的分辨率，使任务绩效更具可预测性。尽管做出了这些努力，但仍然需要更多关于LLM工作机制的基础研究（例如，grokking10）来了解某些能力的出现。尺度定律与涌现能力之间的微妙关系可以通过类比人类的能力习得来解释11。以口语能力为例。对于儿童来说，语言发展（尤其是婴儿）也可以被认为是一个多层次的过程，其中发生了“紧急能力”。特别是，语言能力在一段时间内会相对稳定，但只有当进化到另一个能力水平（例如，从说简单的单词到说简单的句子）时才会发生质的变化。这样的学习过程本质上是不顺利和稳定的（即语言能力不会随着时间的推移以恒定的速度发展），尽管孩子实际上在成长每天。有趣的是，年轻的父母经常会对婴儿表现出的口语能力的意外进步感到惊讶。

LLM 的关键技术。LLMs发展到目前的状态已经走了很长一段路：普通和有能力的学习者。在开发过程中，提出了许多重要的技术，这些技术在很大程度上提高了LLM的能力。在这里，我们简要地列出了（可能）导致 LLM 成功的几种重要技术，如下所示。

•缩放。正如前几部分所讨论的，Transformer语言模型中存在明显的缩放效应：更大的模型/数据大小和更多的训练计算通常会导致模型容量的提高[30,34]。作为两个具有代表性的模型，GPT-3 和 PaLM 分别通过将模型大小增加到 175B 和 540B 来探索缩放极限。由于计算预算通常是有限的，因此可以进一步采用缩放定律来对计算资源进行更高效的计算分配。例如，Chinchilla（具有更多的训练令牌）通过在相同的计算预算下增加数据规模而优于其对应模型Gopher（具有更大的模型大小）[34]。此外，数据缩放应经过仔细的清理，因为预训练数据的质量在模型容量中起着关键作用。

•训练。由于模型规模巨大，成功训练有能力的LLM是非常具有挑战性的。需要分布式训练算法来学习LLM的网络参数，其中经常联合使用各种并行策略。为了支持分布式训练，已经发布了几个优化框架来促进并行算法的实现和部署，例如 DeepSpeed [74] 和 Megatron-LM [75–77]。此外，优化技巧对于训练稳定性和模型性能也很重要，例如，重启以克服训练损失峰值[56]和混合精度训练[78]。最近，GPT-4 [46] 提议开发特殊的基础设施和优化方法，以可靠地预测具有小得多模型的大型模型的性能。

• 能力引出。在对大规模语料库进行预训练后，LLM 被赋予了作为通用任务求解器的潜在能力。当 LLM 执行某些特定任务时，可能不会显式展示这些能力。作为技术方法，设计合适的任务说明或特定的上下文学习策略来激发这些能力是有用的。例如，思维链提示已被证明通过包括中间推理步骤来解决复杂的推理任务很有用。此外，我们可以对用自然语言表达的任务描述对 LLM 进行指令调整，以提高 LLM 在看不见的任务上的泛化性。这些引出技术主要对应于LLM的涌现能力，而LLM在小型语言模型上可能不会显示出相同的效果。

• 对齐调整。由于 LLM 经过训练可以捕获预训练语料库的数据特征（包括高质量和低质量数据），因此它们可能会对人类产生有毒、有偏见甚至有害的内容。有必要使 LLM 与人类价值观保持一致，例如，乐于助人、诚实和无害。为此，InstructGPT [66] 7 设计了一种有效的调优方法，使 LLM 能够遵循预期的指令，该方法利用了具有人类反馈的强化学习技术 [66， 79]。它将人类与精心设计的标签策略结合到训练循环中。ChatGPT 确实是在与 InstructGPT 类似的技术上开发的，它在产生高质量、无害的响应（例如拒绝回答侮辱性问题）方面表现出很强的对齐能力。

• 工具操作。从本质上讲，LLM 被训练为大量纯文本语料库上的文本生成器，因此在无法最好地以文本形式表达的任务（例如，数值计算）上表现不佳。此外，它们的能力也仅限于训练前数据，例如，无法捕获最新信息。为了解决这些问题，最近提出的一种技术是使用外部工具来弥补LLM的不足[80,81]。例如，LLM可以利用计算器进行精确计算[80]，并使用搜索引擎来检索未知信息[81]。最近，ChatGPT 启用了使用外部插件（现有或新创建的应用程序）12 的机制，这些插件类似于 LLM 的“眼睛和耳朵”。这种机制可以广泛地扩大LLM的能力范围。

此外，许多其他因素（例如，硬件的升级）也有助于 LLM 的成功。 目前，我们将讨论限制在开发 LLM 的主要技术方法和关键发现上。

## 2. GPT系列模型的技术演进

由于与人类交流能力强，ChatGPT自发布以来就点燃了AI社区的热潮。ChatGPT 基于强大的 GPT 模型开发，具有特别优化的对话能力。考虑到人们对ChatGPT和GPT模型的兴趣与日俱增，我们增加了对GPT系列模型技术演变的特别讨论，以简要总结它们在过去几年的发展进展。同时，我们绘制了图 4 中 GPT 系列模型的技术演变示意图。GPT 模型的基本原理是通过语言建模将世界知识压缩到仅解码器的 Transformer 模型中，这样它就可以恢复（或记忆）世界知识的语义，并作为通用任务求解器。成功的两个关键点是 （I） 训练可以准确预测下一个单词的纯解码器 Transformer 语言模型，以及 （II） 扩大语言模型的规模。总体而言，OpenAI 对 LLM 的研究大致可分为以下几个阶段。

早期探索。根据对 Ilya Sutskever14（OpenAI 的联合创始人兼首席科学家）的一次采访，用语言接近智能系统的想法在OpenAI的早期，人们已经探索了模型，而使用递归神经网络（RNN）则进行了尝试[121]。随着 Transformer 的出现，OpenAI 开发了两个最初的 GPT 模型，即 GPT-1 [122] 和 GPT-2 [26]，可以将其视为随后更强大的模型（即 GPT-3 和 GPT-4）的基础。

• GPT-1。2017 年，Google 推出了 Transformer 模型 [22]，OpenAI 团队迅速调整了他们的语言建模工作以适应这种新的神经网络架构。他们在 2018 年发布了第一个 GPT 模型，即 GPT-1 [122]，并创造了缩写术语 GPT 作为模型名称，代表生成预训练。GPT-1 是基于生成式、仅解码器的 Transformer 架构开发的，并采用了无监督预训练和监督微调的混合方法。GPT1 为 GPT 系列模型建立了核心架构，并建立了对自然语言文本进行建模的基本原理，即预测下一个单词。

• GPT-2。遵循 GPT-1 的类似架构，GPT-2 [26] 将参数尺度增加到 1.5B，该尺度使用大型网页数据集 WebText 进行训练。正如 GPT-2 的论文所声称的那样，它试图通过无监督语言建模来执行任务，而无需使用标记数据进行显式微调。为了激励这种方法，他们引入了一种用于多任务求解的概率形式，即p（output|input， task）（在[123]中采用了类似的方法），它根据输入和任务信息预测输出。为了对这种条件概率进行建模，语言文本可以自然地用作格式化输入、输出和任务信息的统一方式。这样，解决任务的过程可以转换为生成解决方案文本的单词预测问题。此外，他们为这个想法引入了一个更正式的声明：“由于（特定于任务的）监督目标与无监督（语言建模）目标相同，但仅在序列的子集上进行评估，因此无监督目标的全局最小值也是监督目标的全局最小值（对于各种任务）”[26]15。对这一说法的基本理解是，每个（NLP）任务都可以被视为基于世界文本子集的单词预测问题。因此，无监督语言建模可以解决各种任务，如果它被训练为具有足够的恢复世界文本的能力。GPT-2 论文中的这些早期讨论在 Jensen Huang 对 Ilya Sutskever 的采访中得到了呼应：“神经网络学习的是产生文本的过程的一些表示。这段文字其实是世界的投射......你预测下一个单词越准确，保真度就越高，你在这个过程中得到的分辨率就越高......“16 。

容量飞跃。尽管 GPT-2 旨在成为“无监督的多任务学习器”，但与有监督的微调最先进的方法相比，它的整体性能较差。由于它的模型大小相对较小，因此在下游任务中进行了广泛的微调，尤其是对话任务[124,125]。基于 GPT-2、GPT-3通过扩展（几乎相同的）生成式预训练架构，展示了关键的容量飞跃。

• GPT-3。GPT-3 [55] 于 2020 年发布，它将模型参数缩放到更大的 175B 大小。在 GPT-3 的论文中，它正式引入了上下文学习 （ICL）17 的概念，它以少数或零样本的方式利用 LLM。ICL可以教授（或指导）LLM以自然语言文本的形式理解任务。使用 ICL，LLM 的预训练和利用收敛到相同的语言建模范式：预训练根据上下文预测以下文本序列，而 ICL 预测正确的任务解决方案，该解决方案也可以根据任务描述格式化为文本序列。GPT-3 不仅在各种 NLP 任务中表现出非常出色的表现，而且在许多需要推理或领域适应能力的专门设计任务中也表现出非常出色的表现。尽管 GPT-3 的论文没有明确讨论 LLM 的涌现能力，但我们可以观察到可能超越基本缩放定律 [30] 的大幅性能飞跃，例如，更大的模型具有更强的 ICL 能力（如 GPT-3 论文的原始图 1.2 所示 [55]）。总的来说，GPT-3 可以被视为从 PLM 到 LLM 演变过程中的一个非凡里程碑。经验证明，将神经网络扩展到相当大的规模可以导致模型容量的大幅增加。

容量增强。由于强大的能力，GPT3 一直是为 OpenAI 开发功能更强大的 10 个 LLM 的基本模型。总体而言，OpenAI 探索了两种主要方法来进一步改进 GPT-3 模型，即代码数据训练和与人类偏好保持一致，详情如下。

• 代码数据训练。原始 GPT-3 模型（在纯文本上预先训练）的一个主要局限性在于缺乏复杂任务的推理能力，例如完成代码和解决数学问题。为了增强这种能力，OpenAI 于 2021 年 7 月推出了 Codex [105]，这是一个在大型 GitHub 代码语料库上微调的 GPT 模型。它表明Codex可以解决非常困难的编程问题，并且还可以显著提高解决数学问题的性能[126]。此外，2022年1月报道了一种训练文本和代码嵌入的对比方法[127]，该方法被证明可以改善一系列相关任务（即线性探针分类、文本搜索和代码搜索）。实际上，GPT-3.5模型是基于基于代码的GPT模型（即code-davinci-002）开发的，这表明对代码数据进行训练对于提高GPT模型的模型容量，尤其是推理能力非常有用。此外，还有一种推测认为，对代码数据进行训练可以大大提高LLM的思维链提示能力[47]，同时仍然值得进一步研究，进行更彻底的验证。

• 人类对齐。OpenAI 的人类对齐相关研究可以追溯到 2017 年（或更早）：OpenAI 博客上发布了一篇题为“从人类偏好中学习” 的博客文章，描述了一项应用强化学习 （RL） 从人类注释的偏好比较中学习的工作 [79]（类似于图 12 中 InstructGPT 对齐算法中的奖励训练步骤）。在RL论文[79]发布后不久，2017年7月发表了近端策略优化（PPO）[128]的论文，该论文现已成为从人类偏好中学习的基础RL算法[66]。2020 年 1 月下旬，GPT-2 使用上述 RL 算法 [79， 128] 进行了微调，该算法利用人类的偏好来提高 GPT-2 在 NLP 任务上的能力。同年，另一项研究[129]训练了一个总结模型，以类似的方式优化人类偏好。基于这些前期工作，2022 年 1 月提出了 InstructGPT [66] 来改进人类对齐的 GPT-3 模型，该模型正式建立了基于人类反馈的三阶段强化学习 （RLHF） 算法。请注意，OpenAI 的论文和文档中似乎很少使用“指令调优”的措辞，取而代之的是人工演示的监督微调（即 RLHF 算法的第一步 [66]）。除了提高指令跟随能力外，RLHF算法对于缓解LLM产生危害或有毒内容的问题特别有用，这是LLM在实践中安全部署的关键。OpenAI在一篇技术文章[130]中描述了他们的对齐研究方法，该文章总结了三个有前途的方向：“训练AI系统使用人类反馈，协助人类评估和进行对齐研究”。

这些增强技术导致了改进的具有更强能力的 GPT-3 模型，被 OpenAI 称为 GPT-3.5 模型（参见第 3.1 节中关于 OpenAI API 的讨论）。语言模型的里程碑。基于所有的探索努力，OpenAI已经实现了两个重要的里程碑，即ChatGPT [131]和GPT-4 [46]，这在很大程度上提高了现有AI系统的容量标准。

• chatGPT。2022 年 11 月，OpenAI 发布了基于 GPT 模型（GPT-3.5 和 GPT-4）的对话模型 ChatGPT。正如官方博客文章[131]所介绍的那样，ChatGPT的训练方式与InstructGPT类似（在原帖中称为“InstructGPT的兄弟模型”），同时专门针对对话进行了优化。他们报告了 ChatGPT 和 InstructGPT 在数据收集设置中的训练之间的差异：人类生成的对话（同时扮演用户和 AI 的角色）以对话格式与 InstructGPT 数据集相结合，用于训练 ChatGPT。ChatGPT 在与人类交流方面表现出卓越的能力：拥有丰富的知识储备、对数学问题进行推理的技能、在多回合对话中准确追踪上下文以及与人类价值观保持一致以安全使用。后来，ChatGPT 支持插件机制，这进一步扩展了 ChatGPT 与现有工具或应用程序的能力。到目前为止，它似乎是人工智能历史上最强大的聊天机器人。ChatGPT的推出对未来的AI研究产生了重大影响，为类人AI系统的探索提供了启示。

• GPT-4。作为另一项显着进展，GPT-4 [46] 于 2023 年 3 月发布，它将文本输入扩展到多模态信号。总体而言，GPT-4 在解决复杂任务方面的能力比 GPT-3.5 更强，在许多评估任务上显示出巨大的性能提升。最近的一项研究[41]通过对人为生成的问题进行定性测试，调查了GPT-4的能力，涵盖了各种困难的任务，并表明GPT-4可以实现比以前的GPT模型（如ChatGPT）更优越的性能。此外，GPT-4 对恶意或挑衅性查询的响应更安全，这要归功于六个月的迭代对齐（在 RLHF 训练中带有额外的安全奖励信号）。在技术报告中，OpenAI 强调了如何安全地开发 GPT-4，并应用了多种干预策略来缓解 LLM 可能出现的问题，例如幻觉、隐私和过度依赖。例如，他们引入了称为红队[132]的机制，以减少危害或有毒成分的产生。另一个重要方面是，GPT4 是在完善的深度学习基础设施上开发的，优化方法得到改进。他们引入了一种称为可预测缩放的新机制，该机制可以在模型训练期间使用一小部分计算来准确预测最终性能。

• GPT-4V、GPT-4 turbo 等。基于对 GPT-4 所做的工作 [46]，OpenAI 于 2023 年 9 月进一步发布了 GPT-4V，重点关注 GPT-4 视觉能力的安全部署。在GPT-4V的系统卡[133]中，它广泛讨论了与视觉增强输入相关的风险评估和缓解。特别是，GPT-4V在各种应用场景中表现出了强大的视觉能力，显示出作为强大的多模态学习系统的巨大潜力。最近，在 2023 年 11 月，OpenAI 在 DevDay 上发布了升级版 GPT-4 模型，名为 GPT-4 Turbo，并进行了一系列技术改进。GPT-4 Turbo 的特点是改进的模型容量（比 GPT4 更强大）、扩展的知识源（截至 2023 年 4 月）、长上下文窗口（最多 128k 个令牌）、优化的模型性能（更便宜的价格）和其他有用的功能更新（函数调用、可重复输出等）。同时，Assistants API推出，以简化类代理助手的快速开发。借助此 API，开发人员可以通过利用特定指令、额外知识和工具使用，轻松地在其应用程序中创建面向目标的助手。此外，多模态能力（看、听和说）也在这个新版本中得到增强，由具有视觉的 GPT-4 Turbo 支持，DALL·E 3、文本转语音 （TTS） 和收听语音示例。这些改进极大地扩展了 GPT 模型的容量范围并增强了任务性能。更重要的是，随着模型、API和功能的改进，应用生态将得到极大的加强。

尽管取得了巨大的进展，但这些优秀的LLM仍然存在局限性，例如，在某些特定情况下产生带有事实错误或潜在风险反应的幻觉[46]。LLM 的更多限制或问题将在第 7 节中讨论。它带来了长期的研究挑战，以开发更强大、更安全的 LLM。从工程学的角度来看，OpenAI采用迭代部署策略[134]，通过五个阶段的开发和部署生命周期来开发模型和产品，旨在有效降低使用模型的潜在风险。在下文中，我们将深入探讨技术细节，以便具体了解它们的开发方式。

## 3. LLMS的资源

考虑到具有挑战性的技术问题和巨大的计算资源需求，开发或复制LLM绝不是一件容易的事。一个可行的方法是从现有的 LLM 中学习经验，并重用公开可用的资源进行增量开发或实验研究。在本节中，我们简要总结了用于开发 LLM 的公开资源，包括模型检查点（或 API）、语料库和库。

### 3.1 公开可用的模型检查点或 API

鉴于模型预训练的巨大成本，训练有素的模型检查点对于研究界 LLM 的研究和开发至关重要。由于参数尺度是使用LLM时需要考虑的关键因素，因此我们将这些公共模型分为两个尺度级别（即数百亿个参数和数千亿个参数），这有利于用户根据自己的资源预算识别合适的资源。此外，对于推理，我们可以直接使用公共 API 来执行我们的任务，而无需在本地运行模型。接下来，我们介绍公开可用的模型检查点和 API。

具有数百亿个参数的模型。除了LLaMA [57]和LLaMA2 [99]（最大版本包含70B参数）、NLLB [91]（最大版本包含54.5B参数）和Falcon [135]（最大版本包含40B参数）之外，该类别中的大多数模型的参数范围从10B到20B。此范围内的其他模型包括 mT5 [83]、PanGu-α [84]、T0 [28]、GPT-NeoX-20B [87]、CodeGen [86]、UL2 [89]、Flan-T5 [69] 和 mT0 [94]。其中，FlanT5（11B版）可以作为指令调优研究的首要模型，因为它从三个方面探索指令调优[69]：增加任务数量、扩展模型大小和使用思维链提示数据进行微调。此外，CodeGen（11B版）作为为生成代码而设计的自回归语言模型，可以被认为是探索代码生成能力的良好候选者。它还引入了一个新的基准 MTPB [86]，专门用于多轮程序合成，它由 115 个专家生成的问题组成。为了解决这些问题，它要求 LLM 获得足够的编程知识（例如，数学、数组运算和算法）。最近，CodeGen2 [97] 发布，以探索模型架构、学习算法和数据分布中的选择对模型的影响。作为另一位专门研究编码能力的LLM，StarCoder[98]也取得了优异的成绩。至于多语言任务，mT0（13B 版本）可能是一个很好的候选模型，它已经在带有多语言提示的多语言任务上进行了微调。

此外，基于深度学习框架MindSpore[136]开发的PanGu-α [84]在零样本或少样本设置下的中国下游任务中表现出良好的性能。请注意，PanGu-α [84] 拥有多个版本的模型（最多 200B 参数），而最大的公共版本有 13B 参数。作为一种流行的LLM，LLaMA（65B版本）[57]包含的参数大约是其他模型的五倍，在与指令跟踪相关的任务中表现出卓越的性能。与 LLaMA 相比，LLaMA2 [99] 在人类反馈强化学习 （RLHF） 方面进行了更多探索，并开发了一个名为 LLaMA-chat 的面向聊天的版本，该版本在一系列有用性和安全性基准上通常优于现有的开源模型。由于LLaMA的开放性和有效性，它引起了研究界的极大关注，许多工作[137‒140]都致力于微调或不断预训练其不同的模型版本，以实现新的模型或工具。最近，Falcon [135]作为另一个开源LLM，在开放基准测试中也取得了非常出色的性能。它的特点是更仔细的数据清理过程来准备预训练数据（使用公开共享的数据集RefinedWeb [141]）。通常，这种规模的预训练模型需要数百甚至数千个 GPU 或 TPU。例如，GPT-NeoX-20B 使用 12 台超微服务器，每台服务器配备 8 个 NVIDIA A100-SXM4-40GB GPU，而 LLaMA 使用 2,048 个 A100-80G GPU，正如其原始出版物中所报道的那样。为了准确估计所需的计算资源，建议使用衡量相关计算数量的指标，例如FLOPS（即FLoating点数每秒操作数）[30]。
![图片](../images/2024/06/16/llm_survey/image8.png "llama")

具有数千亿个参数的模型。对于此类别的模型，只有少数模型已公开发布。例如，OPT [90]、OPT-IML [95]、BLOOM [78] 和 BLOOMZ [94] 的参数数量与 GPT-3（175B 版本）几乎相同，而 GLM [93] 和 Galactica [35] 的参数数量分别为 130B 和 120B。其中，OPT（175B版本）和指令调谐版本OPT-IML是专门为开放共享而设计的，旨在使研究人员能够大规模地进行可重复的研究。对于跨语言泛化的研究，BLOOM（176B版）和BLOOMZ（176B版）可以作为基础模型，因为具有多语言语言建模任务的能力。作为双语LLM，GLM还提供了流行的小型中文聊天模型ChatGLM2-6B（ChatGLM-6B的更新版本），该模型在效率和容量方面有许多改进（例如，量化，32K长度的上下文，快速推理速率）。这种规模的模型通常需要数千个 GPU 或 TPU 来训练。例如，OPT（175B 版本）使用 992 个 A100-80GB GPU，而 GLM（130B 版本）使用 96 个 NVIDIA DGX-A100 （8x40G） GPU 节点的集群。

LLaMA 模型系列。Meta AI 于 2023 年 2 月推出了 LLaMA 模型集合 [57]，包括四种尺寸（7B、13B、30B 和 65B）。自发布以来，LLaMA引起了研究界和业界的广泛关注。LLaMA模型在各种开放基准测试中取得了非常出色的性能，成为迄今为止最受欢迎的开放语言模型。大量研究人员通过指令调整或持续预训练来扩展 LLaMA 模型。特别是，由于计算成本相对较低，指令调优 LLaMA 已成为开发定制或专用模型的主要方法。为了有效地适应非英语语言的LLaMA模型，它通常需要扩展原始词汇（主要在英语语料库上训练）或使用目标语言的指令或数据对其进行微调。在这些扩展模型中，Stanford Alpaca [142]是第一个基于LLaMA（7B）微调的开放式指令跟踪模型。它由 52K 指令跟踪演示训练，这些演示通过 selfinstruct [143] 使用 text-davinci-003 生成。名为Alpaca-52K的指令数据和训练代码在随后的工作中被广泛采用，例如AlpacaLoRA [144]（使用LoRA [145]复制斯坦福Alpaca），Koala [146]和BELLE [147]。此外，Vicuna [138] 是另一种流行的 LLaMA 变体，根据从 ShareGPT [148] 收集的用户共享对话进行训练。由于 LLaMA 的出色性能和可用性。

LLM 的公共 API。API 不是直接使用模型副本，而是为普通用户提供了一种更方便的方式来使用 LLM，而无需在本地运行模型。作为使用 LLM 的代表性接口，GPT 系列模型的 API [46， 55， 66， 105] 已被学术界和工业界广泛使用。OpenAI 为 GPT-3 系列中的模型提供了七个主要接口：ada、babbage、curie、davinci（GPT-3 系列中最强大的版本）、text-ada-001、text-babbage-001 和 text-curie-001。其中，前四个接口可以在OpenAI的主机服务器上进一步微调。特别是，巴贝奇、居里和达芬奇分别对应于GPT-3（1B）、GPT-3（6.7B）和GPT-3（175B）模型[55]。此外，还有两个与Codex [105]相关的API，分别称为code-cushman-001（Codex（12B）[105]的强大多语言版本）和code-davinci-002。此外，GPT-3.5 系列包括一个基本型号代码-davinci-002 和三个增强版本，即 text-davinci-002、text-davinci-003 和 gpt-3.5-turbo。作为更强大的替代品，今年 OpenAI 发布了 GPT-4 系列的模型接口，包括 gpt-4、gpt-4-32k、gpt-4-1106-preview（即 GPT-4 Turbo）和 gpt-4-vision-preview（即 GPT-4 Turbo with vision，一种多模态模型）。值得注意的是，OpenAI 一直在维护和升级这些模型接口（gpt-3.5-turbo、gpt-4、gpt-4-32k），因此 API 名称实际上会指向最新版本。目前，ChatGPT 可以由 GPT-3.5 或 GPT-4 模型提供支持。总体来说，根据具体的应用场景和响应要求来选择合适的模型接口。详细的用法可以在他们的项目网站上找到。

### 3.2 用于预训练的常用语料库

与早期的 PLM 相比，由大量参数组成的 LLM 需要更高的数量.涵盖广泛内容的训练数据。为了满足这一需求，已经发布了越来越多的可访问的训练数据集用于研究。在本节中，我们将简要总结几个广泛使用的用于训练 LLM 的语料库。 根据它们的内容类型，我们将这些语料库分为六组：书籍、CommonCrawl、Reddit 链接、维基百科、代码等。书。

**BookCorpus** [153] 是以前的小规模模型（例如 GPT [122] 和 GPT-2 [26]）中常用的数据集，由超过 11,000 本涵盖广泛主题和类型（例如小说和传记）的书籍组成。另一个大型图书语料库是古腾堡计划[154]，由70,000多本文学书籍组成，包括小说，散文，诗歌，戏剧，历史，科学，哲学和其他类型的公有作品。它是目前最大的开源书籍收藏之一，用于MT-NLG [113]和LLaMA [57]的训练。至于 GPT-3 [55] 中使用的 Books1 [55] 和 Books2 [55]，它们比 BookCorpus 大得多，但到目前为止尚未公开发布。

**CommonCrawl** 中。CommonCrawl [163] 是最大的开源网络爬虫数据库之一，包含 PB 级的数据量，已被广泛用作现有 LLM 的训练数据。由于整个数据集非常大，现有的研究主要从中提取特定时期内的网页子集。然而，由于Web数据中普遍存在嘈杂和低质量的信息，因此有必要在使用前进行数据预处理。基于 CommonCrawl，现有工作中常用四个过滤数据集：C4 [82]、CCStories [155]、CC-News [27] 和 RealNews [156]。Colossal Clean Crawled Corpus （C4） 包括五个变体21 ，即 en （806G）、en.noclean （6T）、realnewslike （36G）、webtextlike （17G） 和多语言 （38T）。en 版本已用于预训练 T5 [82]、LaMDA [68]、Gopher [64] 和 UL2 [89]。多语言C4，也称为mC4，已用于mT5[83]。CC-Stories （31G） 由 CommonCrawl 数据的子集组成，其中的内容以类似故事的方式制作。由于 CC-Stories 的原始来源现在不可用，我们在表 2 中包括了一个复制版本 CC-Stories-R [164]。此外，从CommonCrawl中提取的两个新闻语料库，即REALNEWS（120G）和CC-News（76G）也常被用作预训练数据。

**Reddit链接**。Reddit 是一个社交媒体平台，使用户能够提交链接和文本帖子，其他人可以通过“赞成票”或“反对票”对其进行投票。高投票的帖子通常被认为是有用的，可用于创建高质量的数据集。WebText [26] 是一个著名的语料库，由来自 Reddit 的高度点赞链接组成，但它并不公开。作为替代项，有一个易于访问的开源替代方案，称为 OpenWebText [157]。另一个从Reddit提取的语料库是 PushShift.io [158]，这是一个实时更新的数据集，由Reddit自创建以来的历史数据组成。Pushshift 不仅提供每月数据转储，还提供有用的实用工具，以支持用户搜索、汇总和执行对整个数据集进行 14 项初步调查。这使得用户可以轻松收集和处理 Reddit 数据。

**维基百科**。维基百科[159]是一本在线百科全书，包含大量关于不同主题的高质量文章。这些文章中的大多数都是以说明性写作风格（带有支持性参考文献）撰写的，涵盖了广泛的语言和领域。通常，维基百科的纯英语过滤版本在大多数 LLM 中被广泛使用（例如，GPT-3 [55]、LaMDA [68] 和 LLaMA [57]）。维基百科有多种语言版本，因此可以在多语言环境中使用。

**code**。为了收集代码数据，现有工作主要从 Internet 上抓取开源许可代码。两个主要来源是开源许可证下的公共代码存储库（例如，GitHub）和与代码相关的问答平台（例如，StackOverflow）。Google已经公开发布了BigQuery数据集[160]，其中包括大量各种编程语言的开源许可代码片段，作为代表性的代码数据集。CodeGen 利用 BigQuery 数据集的一个子集 BIGQUERY [86] 来训练 CodeGen 的多语言版本 （CodeGen-Multi）。

**other**。The Pile [161] 是一个大规模、多样化和开源的文本数据集，由来自多个来源的超过 800GB 的数据组成，包括书籍、网站、代码、科学论文和社交媒体平台。它由 22 个不同的高质量子集构成。Pile数据集广泛应用于不同参数尺度的模型，如GPT-J（6B）[165]、CodeGen（16B）[86]和Megatron-Turing NLG（530B）[113]。ROOTS [162]由各种较小的数据集（总共1.61 TB的文本）组成，涵盖59种不同的语言（包含自然语言和编程语言），这些语言已被用于训练BLOOM [78]。
![图片](../images/2024/06/16/llm_survey/image9.png "表2")

在实践中，它通常需要混合使用不同的数据源来进行预训练 LLM（参见图 6），而不是单个语料库。因此，现有的研究通常混合几个现成的数据集（例如，C4、OpenWebText 和 Pile），然后进行进一步处理以获得预训练语料库。此外，为了训练适应特定应用程序的 LLM，从相关来源（例如 Wikipedia 和 BigQuery）中提取数据以丰富预训练数据中的相应信息也很重要。为了快速参考现有 LLM 中使用的数据源，我们提供了三个代表性 LLM 的预训练语料库：

• GPT-3 （175B） [55] 在 300B token的混合数据集上进行训练，包括 CommonCrawl [163]、WebText2 [55]、Books1 [55]、Books2 [55] 和 Wikipedia [159]。

• PaLM （540B） [56] 使用 780B token的预训练数据集，该数据集来自社交媒体对话、过滤网页、书籍、Github、多语言维基百科和新闻。

• LLaMA [57] 从各种来源提取训练数据，包括 CommonCrawl、C4 [82]、Github、Wikipedia、books、ArXiv 和 StackExchange。LLaMA （6B） 和 LLaMA （13B） 的训练数据大小为 1.0T token，而 LLaMA （32B） 和 LLaMA （65B） 的训练数据大小为 1.4T token。

### 3.3 微调常用数据集

预训练后，需要对LLM进行进一步的微调，以增强模型容量，这通常涉及两个主要步骤，即指令调优（监督微调）和对齐调优。在本节中，我们主要讨论两种调优方法的相关可用数据集，更多算法细节可以在第 5 节中找到。

### 3.3.1 指令调优数据集

在预训练之后，指令调优（又称监督微调）是增强或解锁 LLM 特定能力（例如，指令遵循）的重要方法。在这一部分，我们介绍了几种广泛使用的指令调优数据集，并根据格式化指令实例的构建方法将它们分为三种主要类型，即NLP任务数据集、日常聊天数据集和合成数据集。我们在表 3 中显示了它们的详细信息。
![图片](../images/2024/06/16/llm_survey/image10.png "表")

**NLP 任务数据集**。这类数据集的格式基于收集的NLP任务数据集（例如，文本分类和摘要），并附有相应的自然语言任务描述。在此类别中，P3 [182] 和 FLAN [67， 183] 是两个广泛使用的指令调优数据集。

• P3 [182] 由 170 个英语 NLP 数据集和 2,052 个英语提示模板组成，其中每个数据示例的输入和输出都使用特定的提示模板进行格式化，用于编写训练实例。

• FLAN [67] 由 62 个广泛使用的 NLP 基准测试组成。最近，还提出了FLAN-v2 [183]，它通过混合其他指令数据集来扩展FLAN，包括Muffin [67]、NIV2 [88]、T0-SF [28]和CoT [184‒186]。Muffin 包含来自原始 FLAN 的 62 个任务和其他 26 个任务，包括对话和代码合成任务。T0-SF是从T0 [28]中提取的，同时确保与松饼没有重叠。NIV2 指的是 Natural-Instructions v2 数据集 [88]，而 CoT [184–186] 是九个推理任务与相应的思维链提示和输出的组合。

**日常聊天数据集**。这种数据集是基于真实的用户对话构建的，其中查询由人类提出，响应主要由人类标记器或 LLM（例如 ChatGPT、GPT-4）生成。对话类型包括开放式生成、问答、头脑风暴和聊天。在这个类别中，ShareGPT [148]、OpenAssistant [173] 和 Dolly [172] 是 LLM 微调的三个常用数据集。

• ShareGPT [148] 是从数据收集平台收集的，用户可以通过 ShareGPT API 上传他们与 ChatGPT 或 GPT-4 的对话。目前，该数据集由大约 90,000 个对话组成，包括来自人类的真实指令或查询以及来自 ChatGPT 的响应。

• OpenAssistant [173] 是一个多语言语料库，包含 66,497 个人类和 AI 助手之间的真实世界对话树。每个对话树由多个节点组成，每个节点表示对话中某个角色生成的信息。它涵盖 35 种语言，包括 461,292 个手动注释的回复质量评级。

• Dolly [172] 是一个英语数据集，包含来自 Databricks 的 15,000 个人工生成的数据实例（提示-响应对）。该数据集涵盖了InstructGPT[66]中概述的七个领域，包括头脑风暴、分类、闭卷质量保证、生成、信息提取、开卷质量保证和总结。

**合成数据集**。这类数据集通常是通过指令 LLM 根据预定义的指导规则或方法构建的。在此类别中，Self-Instruct52K [143]、Alpaca [142] 和 Baize [175] 是 LLM 的三个常用合成数据集。

• Self-Instruct-52K [143] 是通过 self-instruct [143] 方法生成的指令数据集，由 82,000 个实例和 52,000 条指令组成。具体来说，作者构建了 175 个种子实例，然后迭代提示 LLM [55] 根据随机选择的 8 条指令作为参考来合成其他指令。随后，进一步指示LLM根据合成指令生成实例输入及其对应的输出，最终得到Self-Instruct52K数据集。

• Alpaca [142] 也是一个基于 selfinstruct [143] 方法的合成数据集。它利用 Self-Instruct-52K 的 175 个种子数据集上的 text-davinci-003 模型来获得 52,000 条新指令和相应的输入和输出。此外，60%的示例是纯指令，最终数据集中没有输入部分。

• Baize [175] 是一个使用 ChatGPT 构建的英语多轮对话语料库，包含 111.5K 个实例。为了创建Baize，一种称为“自聊”[175]的方法被设计出来，ChatGPT轮流扮演用户和AI助手的角色，以对话的形式生成信息。

### 3.3.2 对齐数据集

除了指令调优之外，构建高质量的数据集也很重要，以便使 LLM 与人类的价值观和偏好（例如，乐于助人、诚实和无害）保持一致。在本节中，我们介绍了几个广泛使用的对齐调整数据集，包括 HH-RLHF [170]、SHP [177]、PKU-SafeRLHF [181]、Stack Exchange Preferences [178] 和 Sandbox Alignment Data [179]。我们在表 4 中显示了它们的详细信息。

• HH-RLHF [170] 由大约 169K 个实例组成，可分为两部分，分别关注 LLM 的有用性和无害性。每个实例都是众包工作者和聊天模型之间的开放式对话，关于寻求帮助、建议或完成任务。聊天模型为每个用户查询提供两个响应，将选择更有用或更有害的响应作为注释。

• SHP [177] 侧重于响应的有用性。它包括 385K 个不同主题领域对问题/指示的回答的集体偏好，涵盖从烹饪到法律咨询的主题。每个实例都是一个 Reddit 帖子，其中包含一个问题或说明以及一对顶级评论，其中一个被 Reddit 用户认为更可取，另一个被认为不太有用。与HH-RLHF [170]不同，SHP中的数据由自然发生的和人为的响应组成。

• PKU-SafeRLHF [181] 包含超过 330K 个专家比较数据实例，专注于有用性和无害性。数据集中的每个实例都包括一个问题和两个响应，每个响应都附有安全标签，以及根据有用性和无害性在两个响应之间的两个偏好注释。响应的无害性表明其在所有 14 个危害类别中被归类为风险中性，而响应的有用性是根据其解决问题的有效性来评估的。

• Stack Exchange Preferences [178] 侧重于答案的有用性。它包含来自 Stack Overflow 的大约 10M 个问题和答案。每个实例由一个问题和两个以上的相应答案组成。每个答案都带有根据其投票计算的分数和表示是否被选中的标签。

• 沙盒对齐数据 [179] 是一个对齐数据集，包含来自 LLM 而不是人类的反馈。它来自一个名为 SANDBOX 的虚拟交互环境，其中模型模拟与其他模型的社交交互，并根据其他模型的反馈修改响应。数据集包含 169K 个实例，每个实例由一个社会查询、多个响应以及来自其他模型的相应评级组成。

### 3.4 库资源

在这一部分中，我们简要介绍了一系列可用于开发 LLM 的库。

• Transformers [187] 是一个开源的 Python 库，用于使用 Transformer 架构构建模型，该架构由 Hugging Face 开发和维护。它具有简单且用户友好的 API，可以轻松使用和自定义各种预训练模型。它是一个功能强大的库，拥有庞大而活跃的用户和开发人员社区，他们定期更新和改进模型和算法。

• DeepSpeed [74] 是 Microsoft 开发的深度学习优化库（与 PyTorch 兼容），已用于训练许多 LLM，例如 MTNLG [113] 和 BLOOM [78]。它为分布式训练提供了各种优化技术的支持，例如内存优化（ZeRO 技术、梯度检查点）和流水线并行性。

• Megatron-LM [75–77] 是 NVIDIA 开发的深度学习库，用于训练大规模语言模型。它还为分布式训练提供了丰富的优化技术，包括模型和数据并行性、混合精度训练和 FlashAttention。这些优化技术可以大大提高训练效率和速度，实现跨GPU的高效分布式训练。

• JAX [188] 是由 Google 开发的用于高性能机器学习算法的 Python 库，允许用户在具有硬件加速功能（例如 GPU 或 TPU）的阵列上轻松执行计算。它支持在各种设备上进行高效计算，还支持多种功能，例如自动微分和即时编译。

• Colossal-AI [189] 是由 HPC-AI Tech 开发的用于训练大规模 AI 模型的深度学习库。它基于 PyTorch 实现，支持丰富的并行训练策略集合。此外，它还可以使用PatrickStar[190]提出的方法优化异构内存管理。最近，一个名为 ColossalChat [140] 的类似 ChatGPT 的模型已经公开发布，有两个版本（7B 和 13B），它们是使用基于 LLaMA 的 Colossal-AI 开发的 [57]。

• BMTrain [191] 是 OpenBMB 开发的高效库，用于以分布式方式训练具有大规模参数的模型，强调代码简单、资源少、高可用。BMTrain 已经将几种常见的 LLM（例如 Flan-T5 [69] 和 GLM [93]）整合到其模型中心中，开发人员可以直接使用这些模型。

• FastMoE [192] 是 MoE（即专家混合）模型的专门培训库。它是基于 PyTorch 开发的，在其设计中优先考虑效率和用户友好性。FastMoE 简化了将 Transformer 模型传输到 MoE 模型的过程，并在训练期间支持数据并行性和模型并行性。

• vLLM [193] 是一个快速、内存高效且易于使用的 LLM 推理和服务库。为了实现快速推理，它经过特别优化，具有高服务吞吐量、使用 PagedAttention [193] 的有效注意力内存管理、连续批处理和优化的 CUDA 内核。此外，vLLM 还支持各种解码算法、张量并行性和流输出。为了便于与其他系统的集成，vLLM 对 HuggingFace 模型的使用很友好，并且还提供与 OpenAI 兼容的 API 服务器。

• DeepSpeed-MII [194] 也是由 DeepSpeed [74] 开发的内存效率高的 Python 库。它旨在通过优先考虑高吞吐量、低延迟和成本效益来实现 LLM 推理的民主化。DeepSpeed-MII 通过利用四项基本技术实现加速文本生成推理：阻塞 KV 缓存、连续批处理、动态 SplitFuse 和高性能 CUDA 内核。它目前支持三种流行模型架构的 13,000 多个模型，例如 LLaMA [57]、Mistral [195] 和 OPT [90]。

• DeepSpeed-Chat [196] 是一个快速、经济高效且易于使用的系统框架，可以在模型训练期间集成完整的 RLHF 过程。它有三个主要功能：（1）它简化了类似 ChatGPT 的模型的训练和推理过程，可以使用简单的脚本实现多个训练或推理步骤;（2）复制InstructGPT[66]的训练模式，为SFT、奖励模型微调、RLHF三个训练步骤提供完整的流水线;（3）将Deepspeed的训练引擎和推理引擎集成到一个统一的混合引擎（Deepspeed HE）中，用于RLHF训练，实现训练模式和推理模式的无缝切换，并利用DeepSpeed Inference的各种优化。

除了上述库资源外，现有的深度学习框架（如PyTorch[197]、TensorFlow[198]、MXNet[199]、PaddlePaddle[200]、MindSpore[136]和OneFlow[201]）也提供了对并行算法的支持，这些算法通常用于训练大规模模型。

## 4. 预训练

预训练奠定了llm的基础。通过对大规模语料库的预训练，LLM可以获得基本的语言理解和生成技能[55,56]。在这个过程中，预训练语料库的规模和质量对于LLM获得强大的能力至关重要。此外，为了有效地预训练 LLM，需要精心设计模型架构、加速方法和优化技术。在下文中，我们首先讨论第4.1节中的数据收集和处理，然后在第4.2节中介绍常用的模型架构，最后在第4.3节中介绍稳定高效地优化LLM的训练技术。

### 4.1 数据收集和准备

与小规模语言模型相比，LLM 对模型预训练的高质量数据有更强的需求，其模型能力很大程度上依赖于预训练语料库及其预处理方式。在这一部分中，我们将讨论预训练数据的收集和处理，包括数据源、预处理方法，以及对预训练数据如何影响 LLM 性能的重要分析。

#### 4.1.1 数据源

要开发一个有能力的 LLM，关键是从各种数据源中收集大量的自然语言语料库。现有的 LLM 主要利用各种公共文本数据集的混合作为预训练语料库。图 6 显示了许多具有代表性的 LLM 的预训练数据源的分布。

预训练语料库的来源大致可分为两种类型：一般数据和专用数据。大多数 LLM [55， 56， 90] 都使用通用数据，例如网页、书籍和会话文本，因为它们具有庞大、多样和可访问的特性，可以增强 LLM 的语言建模和泛化能力。鉴于LLM表现出令人印象深刻的泛化能力，也有研究将其预训练语料库扩展到更专业的数据集，如多语言数据、科学数据和代码，赋予LLM特定的任务解决能力[35,56,86]。在下文中，我们将介绍这两种类型的预训练数据源及其对 LLM 的影响。有关常用语料库的详细介绍，可以参考第 3.2 节。

常规文本数据。如图 6 所示，绝大多数 LLM 采用通用的预训练数据，例如网页、书籍和会话文本，这些数据提供了各种主题的富文本源。接下来，我们简要总结了三种重要的一般数据。

• 网页。由于互联网的普及，各种类型的数据被创造出来，这使得LLM能够获得多样化的语言知识，并增强其泛化能力[26,82]。为了方便使用这些数据资源，在以前的工作中，从网络上抓取了大量数据，例如CommonCrawl[163]。但是，爬取的 Web 数据往往同时包含高质量的文本（如维基百科）和低质量的文本（如垃圾邮件），因此过滤和处理网页以提高数据质量非常重要。

• 对话文本。会话数据可以增强LLM的对话能力[90]，并可能提高他们在一系列问答任务中的表现[56]。研究人员可以利用公共对话语料库的子集（例如，PushShift.io Reddit语料库）[158,202]或从在线社交媒体收集对话数据。由于在线会话数据通常涉及多个参与者之间的讨论，因此有效的处理方法是将会话转换为树状结构，其中话语链接到它所响应的话语。这样，多方对话树可以划分为多个子对话，这些子对话可以收集在预训练语料库中。此外，一个潜在的风险是，将对话数据过度集成到LLM中可能会导致副作用[90]：陈述性指令和直接疑问句被错误地视为对话的开始，从而导致指令的效力下降。

•书。与其他语料库相比，书籍提供了正式长文本的重要来源，这对 LLM 学习语言知识、模拟长期依赖性以及生成叙述性和连贯性文本具有潜在优势。为了获得开源书籍数据，现有研究通常采用Books3和Bookcorpus2数据集，这些数据集可在Pile数据集中找到[161]。

**专用文本数据**。专用数据集可用于提高 LLM 在下游任务上的特定能力。接下来，我们介绍三种专业数据。• 多语种文本。除了目标语言的文本外，整合多语言语料库还可以增强语言理解和生成的多语言能力。例如，BLOOM [78] 和 PaLM [56] 在其预训练语料库中分别收集了涵盖 46 种和 122 种语言的多语言数据。FLM [102]以几乎相等的比例混合了中文和英文语料库。这些模型在翻译、多语言摘要和多语言问答等多语言任务中表现出令人印象深刻的性能，并取得了与目标语言语料库微调的状态模型相当或更优越的性能。

• 科学文本。科学出版物的日益增长见证了人类对科学的探索。为了加强对LLM的科学知识的理解[35,203]，纳入模型预训练的科学语料库是有用的[35,203]。通过对大量科学文本进行预训练，LLM可以在科学和推理任务中取得令人印象深刻的表现[204]。为了构建科学语料库，现有的工作主要收集arXiv论文、科学教科书、数学网页和其他相关的科学资源。由于科学领域数据的复杂性，例如数学符号和蛋白质序列，通常需要特定的标记化和预处理技术来将这些不同格式的数据转换为可以由语言模型处理的统一形式。

•code。code综合在研究界得到了广泛的研究[105,205–208]，特别是使用经过代码训练的PLM[165,209]。然而，这些 PLM（例如 GPT-J [165]）生成高质量和准确的程序仍然具有挑战性。最近的研究[105,208]发现，在庞大的代码语料库上训练LLM可以大大提高合成程序的质量。生成的程序可以成功通过专家设计的单元测试用例[105]或解决竞争性编程问题[114]。通常，两种类型的代码语料库通常用于预训练 LLM。第一个来源来自编程问答社区，如Stack Exchange [210]。第二个来源来自公共软件存储库，如GitHub [86， 105， 208]，其中收集代码数据（包括注释和文档字符串）以供使用。与自然语言文本相比，代码是编程语言的格式，对应于长程依赖和准确的执行逻辑[211]。最近的一项研究[47]也推测，代码训练可能是复杂推理能力（例如，思维链能力[33]）的来源。此外，研究表明，将推理任务格式化为代码可以帮助LLM生成更准确的结果[211]。

#### 4.1.2 数据预处理

在收集了大量文本数据后，必须对数据进行预处理以构建预训练语料库，特别是去除杂乱、冗余、不相关和潜在有害的数据[56， 64， 212]，这可能会在很大程度上影响LLM的容量和性能。为了方便数据处理，最近的一项研究[213]提出了一个有用的LLM数据处理系统，名为Data-Juicer，它提供了50多个处理运算符和工具。在这一部分中，我们回顾了详细的数据预处理策略，以提高收集数据的质量[64,78,112]。图 7 显示了对 LLM 预训练数据进行预处理的典型管道。

**质量过滤**。为了从收集的语料库中删除低质量的数据，现有工作通常采用两种方法：（1）基于分类器，（2）基于启发式。前一种方法基于高质量的文本训练选择分类器，并利用它来识别和过滤低质量的数据。通常，这些方法[55,56,112]将精心策划的数据（例如，维基百科页面）训练为正实例的二元分类器，将候选样本数据作为负实例进行训练，并预测衡量每个数据示例质量的分数。然而，一些研究[64,112]发现，基于分类器的方法可能会导致无意中删除方言、口语和社会语言中的高质量文本，这可能导致预训练语料库的偏差并减少语料库的多样性。作为第二种方法，一些研究，如BLOOM [78]和Gopher [64]，采用基于启发式的方法，通过一套精心设计的规则来消除低质量的文本，这些规则可以总结如下：

• 基于语言的过滤。如果 LLM 主要用于某些语言的任务，则可以过滤其他语言的文本。

• 基于指标的过滤。关于生成的文本的评估指标，例如困惑度，可用于检测和删除不自然的句子。

• 基于统计的过滤。语料库的统计特征，例如标点符号分布、符号与单词的比例和句子长度，可用于衡量文本质量并过滤低质量数据。• 基于关键字的过滤。根据特定的关键字集，可以识别和删除文本中嘈杂或无用的元素，例如 HTML 标签、超链接、样板和冒犯性词语。

**重复数据消除**。现有研究[214]发现，语料库中的重复数据会降低语言模型的多样性，这可能导致训练过程变得不稳定，从而影响模型性能。因此，有必要对预训练语料库进行重复数据删除。具体而言，可以以不同的粒度执行重复数据消除，包括句子级、文档级和数据集级重复数据消除。首先，应删除包含重复单词和短语的低质量句子，因为它们可能会在语言建模中引入重复模式[215]。在文献层面，现有研究主要依靠文献之间表面特征的重叠率（如单词和n-gram重叠）来检测和删除包含相似内容的重复文献[57,64,78,216]。此外，为了避免数据集污染问题，通过从训练集中删除可能的重复文本来防止训练集和评估集之间的重叠[56]也很重要。研究表明，重复数据消除的三个层次有助于改进LLM的培训[56,217]，在实践中应联合使用。

**减少隐私**。大多数训练前文本数据来自网络资源，包括用户生成的涉及敏感或个人信息的内容，这可能会增加隐私泄露的风险[218]。因此，有必要从预训练语料库中删除个人身份信息 （PII）。一种直接有效的方法是采用基于规则的方法，如关键词发现，来检测和删除PII，如姓名、地址和电话号码[162]。此外，研究人员还发现，LLM在隐私攻击下的脆弱性可归因于预训练语料库中存在重复的PII数据[219]。

tokenizer。标记化也是数据预处理的关键步骤。它旨在将原始文本分割成单个标记的序列，随后将其用作 LLM 的输入。在传统的NLP研究中（例如，使用条件随机字段的序列标记[220]），基于单词的标记化是主要方法，这更符合人类的语言认知。然而，在某些语言中，基于单词的标记化可能会对相同的输入产生不同的分割结果（例如，中文分词），生成包含许多低频词的大量词汇量，并且还存在“词汇不足”的问题。因此，一些神经网络模型使用字符作为最小单位来推导单词表示（例如，ELMo [21]中的CNN单词编码器）。最近，子字分词器在基于 Transformer 的语言模型中被广泛使用，通常包括 BytePair 编码分词化、WordPiece 分词化和 Unigram 分词化。HuggingFace 在 tokenizer22 上维护了一门出色的在线 NLP 课程，并提供了运行示例，我们参考了本课程的初学者。接下来，我们简要介绍三种具有代表性的代币化方法。

• 字节对编码 （BPE） 标记化。BPE最初在1994年被提出为一种通用的数据压缩算法[221]，然后适应NLP进行标记化[222]。它从一组基本符号（例如，字母和边界字符）开始，并迭代地将语料库中两个连续标记的频繁对组合为新标记（称为合并）。对于每次合并，选择标准基于两个连续标记的共现频率：将选择频率最高的一对。合并过程将持续到达到预定义的大小。此外，字节级 BPE 已被用于通过将字节视为合并的基本符号来提高多语言语料库（例如，包含非 ASCII 字符的文本）的标记化质量。采用这种标记化方法的代表性语言模型包括 GPT-2、BART 和 LLaMA。

• WordPiece标记化算法。它最初是由Google在开发语音搜索系统时提出的[223]。然后，它于2016年被用于神经机器翻译系统[224]，并在2018年被采用为BERT的单词分词器[23]。WordPiece 与 BPE 的想法非常相似，即迭代合并连续的代币，而采用略有不同的合并选择标准。为了进行合并，它首先训练一个语言模型，并用它来对所有可能的对进行评分。然后，在每次合并时，它都会选择导致训练数据可能性增加最多的一对。由于 Google 尚未发布 WordPiece 算法的正式实现，HuggingFace 在其在线 NLP 课程中给出了一个更直观的选择度量：根据训练语料库，通过将共现次数除以对中两个标记的出现次数的乘积来对一对进行评分。

• Unigram 标记化。与 BPE 和 WordPiece 不同，Unigram 标记化 [225] 从语料库的一组足够大的可能子字符串或子标记开始，并迭代删除当前词汇表中的标记，直到达到预期的词汇表大小。作为选择标准，它通过假设从当前词汇表中删除某些标记来计算训练语料库可能性的增加。此步骤基于经过训练的 unigram 语言模型执行。为了估计 unigram 语言模型，它采用了期望最大化 （EM） 算法：在每次迭代时，我们首先根据旧语言模型找到当前最优的单词标记化，然后重新估计 unigram 的概率以更新语言模型。在此过程中，动态规划算法（即 Viterbi 算法）用于在给定语言模型的情况下有效地找到单词的最佳分解方式。采用这种标记化方法的代表性模型包括 T5 和 mBART。

尽管利用现有的分词器是权宜之计（例如，OPT [90] 和 GPT-3 [55] 利用 GPT2 的分词器 [26]），但使用专门为预训练语料库设计的分词器可能非常有益 [78]，特别是对于由不同领域、语言和格式组成的语料库。因此，最近的 LLM 经常使用 SentencePiece 库 [226] 专门针对预训练语料库训练定制的分词器，其中包括字节级 BPE 和 Unigram 分词。需要注意的是，BPE中的归一化技术，如NFKC [227]，可能会降低标记化性能[34,64,78]。在扩展现有的 LLM 时（即持续的预训练或指令调整），我们还应该意识到自定义分词器的潜在副作用。例如，LLaMA基于主要由英语文本组成的预训练语料库训练BPE分词器，而派生的词汇表处理非英语数据的能力可能较差，例如，需要更长的推理延迟来生成中文文本。

**关于数据质量影响的讨论**。对于预训练，预训练数据的质量对LLM的模型能力至关重要。 现有研究表明，对低质量语料库（如嘈杂、有毒和重复数据）进行预训练会在很大程度上损害模型的性能[64,214,216,219]。最近的研究，如T5 [82]、GLaM [112]和Gopher [64]，已经调查了数据质量对LLM能力的影响。通过比较在过滤和未过滤语料库上训练的模型的性能，他们得出了类似的结论，即在清理数据上预训练 LLM 可以提高模型性能。更具体地说，数据的重复可能导致“双重下降”（指表现最初恶化后随后改善的现象）[214,228]，甚至使训练过程不堪重负[214]。此外，研究表明，重复数据会降低LLM从上下文中复制的能力，这可能会进一步影响LLM使用上下文学习的泛化能力[214]。因此，如[56， 64， 78， 212]所述，必须利用质量过滤、有毒过滤和重复数据删除等预处理方法来仔细清理预训练语料库（如第4.1.2节所示），以提高训练过程的稳定性并避免影响模型性能。

**数据混合**。由于每种类型的数据源都与 LLM 的某些能力的发展密切相关（参见第 4.1 节中的讨论），因此设置合适的分布来混合这些数据非常重要。数据混合通常设置在全局级别（即整个训练前数据的分布），也可以在不同训练阶段局部设置为不同的比例。在预训练期间，将根据混合比例选择来自不同来源的数据样本：将从权重较大的数据源中抽取更多数据。通常，现有的LLM（如LLaMA [57]）可以对每个源的完整数据进行上采样或下采样，以创建特定的数据混合作为预训练数据。如图 6 所示，现有的 LLM 使用不同的数据混合来构建预训练数据。作为代表性模型，LLaMA [57]的预训练数据主要由网页（80%以上）组成，6.5%的代码数据来自GitHub和StackExchange，4.5%来自书籍，2.5%的科学数据来自arXiv，arXiv已成为训练通用LLM的重要参考。此外，可以使用特殊的数据混合物来促进不同的目的。例如，Falcon [141] 是在纯网页上训练的，而 CodeGen [86] 则大大增加了代码数据量。在实践中，数据混合通常是根据经验确定的，我们总结了几种寻找有效数据混合的常见策略如下：

• 增加数据来源的多样性。最近的研究经验表明，对某个领域的过多数据进行训练会降低LLM在其他领域的泛化能力[35,64]。相比之下，增加数据源的异质性（例如，包括不同的数据源）对于提高LLM的下游性能至关重要[212,229,230]。为了进一步检查不同数据源的影响，一些研究通过逐个删除每个数据源来进行消融实验，并使用专门策划的数据集预训练LLM[212]。研究表明，删除具有高度异质性的数据源（例如，网页）比删除具有低异质性的来源（例如，学术语料库）更严重地影响LLM的能力。

• 优化数据混合。除了手动设置数据混合外，一些研究还提出了优化数据混合以改进模型预训练[59,231]。给定目标下游任务，可以选择在特征空间中具有更高接近度的预训练数据[231]或那些对下游任务性能产生积极影响的数据[232]。此外，为了减少对目标任务的依赖，DoReMi [59]首先使用给定的初始域权重训练一个小的参考模型，然后训练另一个小代理模型，对观察到两个模型之间可能性差异最大的域进行加权。最后，应用代理模型的学习域权重来训练更大的 LLM。以一种更简单的方式，可以使用不同的数据混合训练几个小型语言模型，并选择能够获得最理想性能的数据混合。然而，在这种方法中做出的一个假设是，当以类似的方式训练时，小模型在模型能力或行为上与大模型相似，这在实践中可能并不总是成立。

• 专门针对目标能力。LLM的模型能力很大程度上依赖于数据选择和混合，可以提高特定数据源的比例，以增强某些模型能力[64,212]。例如，数学推理和编码能力可以通过分别使用更多的数学文本和代码数据进行训练来特别增强。此外，在LAMBADA数据集上的实验结果[233]表明，增加书籍数据的比例可以提高模型从文本中捕获长期依赖性的能力，而增加C4数据集的比例[82]可以提高C4验证数据集的性能[64]。通常，确定 21 个数据源与模型能力之间的更多隐式关系非常重要。为了提高LLM中的数学和编码等特定技能，或开发专门的LLM，一种实用的方法是采用多阶段培训方法，例如，可以在两个连续的阶段安排一般和特定技能的数据。这种在多个阶段对 LLM 进行不同来源或比例数据培训的方法也称为“数据课程”，下面将介绍。

数据课程。在准备数据混合后，重要的是要安排将特定数据呈现给 LLM 进行预训练的顺序。研究表明，在某些情况下，为了学习某种技能，按技能顺序学习（例如，基本技能→目标技能）优于仅关注目标技能的语料库的直接学习[234,235]。遵循课程学习的思想[236]，数据课程被提出并广泛应用于模型预训练[234,235,237,238]。它旨在按特定顺序组织 LLM 预训练数据的不同部分，例如，从简单/通用示例开始，逐步引入更具挑战性/专业的示例。更一般地说，它可以广泛地指在预训练期间对不同来源的数据比例进行自适应调整。关于数据课程的现有工作主要集中在持续的预训练上，例如专门的编码 LLM（例如，CodeLLaMA [235]）或长上下文 LLM（例如，LongLLaMA [238]）。然而，它仍然缺乏关于通用LLM（例如LLaMA）数据课程的更详细的报告。为了确定数据课程，一种实用的方法是根据专门构建的评估基准来监控LLM关键能力的发展，然后在预训练期间自适应地调整数据组合。接下来，我们以三种常见能力为例，介绍数据课程23的概念如何应用于持续的预训练。

•编码。为了提高LLM的编码能力，基于LLaMA 2[99]（2T通用令牌→500B代码重型令牌）开发了CodeLLaMA[235]，旨在提高代码生成能力，保留自然语言理解能力。CodeLLaMA 还提供了一个进一步专门针对特定编程语言的版本，即 CodeLLaMA-Python（2T 通用令牌→ 500B 代码密集型令牌→ 100B Python 重令牌）。

•数学。Llemma [239] 旨在增强通用 LLM 的数学能力。它是基于CodeLLaMA开发的。尽管CodeLLaMA [235]主要关注编码能力，但实验表明，在数学基准测试中，它的表现优于其基础模型LLaMA 2[239]。基于CodeLLaMA，Llemma不断接受科学论文、包含数学文本和代码的网络数据（2T通用令牌→500B代码密集型令牌→50∼200B数学密集型令牌）的混合训练。请注意，Llemma 的预训练数据还包含 5% 的一般域数据作为正则化的一种形式。

• 长上下文。长上下文建模是 LLM 的一项重要能力，许多研究已经探索了扩展通过持续训练来构建LLM的上下文窗口[235,238]。通过对基于RoPE的LLM的位置嵌入（即位置插值）[57,99,240]的修改，CodeLLaMA进一步扩展了LLaMA 2的上下文窗口（2.5T令牌具有4K上下文窗口→20B令牌具有16K上下文窗口）。LongLLaMA [238]还借助外部存储器和独特的训练目标（具有2K上下文窗口的1T令牌→具有8K上下文窗口的10B令牌）实现了更长的上下文窗口。

#### 4.1.4 数据准备总结

在这一部分中，我们总结了LLM准备预训练数据的一般程序和要点，具体表现在以下三个方面。

•数据采集。建议在预训练数据中包括不同的数据源。尽管 Falcon [141] 表明，仅网页就可以用来训练强大的 LLM，但更典型的方法是同时包含各种高质量的文本，如代码、书籍、科学论文等。如果一个LLM是专门具备一定技能的，则应相应增加相应数据源的比例。例如，Gopher [64] 和 Chinchilla [34] 使用大约 40% 的书本数据进行训练。PaLM [44] 和 LaMDA [68] 使用大约 50% 的对话数据。

• 数据清理。数据收集后，清理原始语料库以尽可能提高其质量至关重要。首先，重复数据删除在现有工作中常用[99,141,229]。其次，应以不同的粒度（例如，文档、段落或句子）删除低质量文本、有毒内容和涉及隐私问题的数据。在实践中，启发式和基于分类器的方法都可以用于质量和毒性过滤（例如，CCNet [241]、fastText [242] 和 Data-Juicer [243]）。第三，使用清理后的数据，可以进一步统一或指定预训练数据的格式，并通过使用SentencePiece等库在过滤和删除重复数据的语料库上训练标记器来执行标记化[226]。

• 数据调度。使用预处理的数据，下一步是确定预训练 LLM 的数据组合和数据的特定顺序。为了确定这两种设置，一种实用的方法是首先训练几个具有多个候选计划的小型语言模型，然后在其中选择一个好的计划[59]。总体而言，找到合适的数据课程更加困难。在实践中，可以监控中间模型检查点在特定评估基准上的性能，并在预训练期间动态调整数据混合和分布。在这个过程中，探索数据源和模型能力之间的潜在关系也很有用，以指导数据课程的设计。

在本节中，我们回顾了 LLM 的架构设计，即主流架构、预训练目标和详细配置。表 5 列出了几个具有代表性的 LLM 的模型卡，并提供了公开的详细信息。

#### 4.2.1 典型架构

由于出色的并行性和容量，Transformer 架构 [22] 已成为事实上的骨干开发各种 LLM，使语言模型扩展到数千亿或数千亿个参数成为可能。一般来说，现有 LLM 的主流架构大致可以分为三种主要类型，即编码器-解码器、因果解码器和前缀解码器，如图 9 所示。
![图片](../images/2024/06/16/llm_survey/image12.png "架构")

**编码器-解码器体系结构**。原版Transformer模型建立在编码器-解码器架构[22]上，该架构由两个Transformer模块堆栈组成，分别作为编码器和解码器。编码器采用堆叠的多头自注意力层对输入序列进行编码，以生成其潜在表征，而解码器则对这些表示进行交叉关注并自回归生成目标序列。编码器-解码器 PLM（例如 T5 [82] 和 BART [24]）在各种 NLP 任务中显示出有效性。到目前为止，只有少数基于编码器-解码器架构构建的 LLM，例如 Flan-T5 [69]。我们将在第 4.2.6 节中详细讨论架构选择。

**因果解码器架构**。因果解码器架构包含单向注意力掩码，以保证每个输入令牌只能关注过去的令牌和自身。输入和输出令牌通过解码器以相同的方式进行处理。GPT系列模型[26， 55， 122]作为该架构的代表性语言模型，是基于因果解码器架构开发的。特别是，GPT-3 [55] 成功地证明了这种架构的有效性，也展示了 LLM 惊人的上下文学习能力。 有趣的是，GPT-1 [122] 和 GPT2 [26] 并没有表现出像 GPT-3 那样优越的能力，似乎缩放在增加该模型架构的模型容量方面起着重要作用。到目前为止，因果解码器已被各种现有的 LLM 广泛采用作为 LLM 的架构，例如 OPT [90]、BLOOM [78] 和 Gopher [64]。请注意，下面讨论的因果解码器和前缀解码器都属于仅解码器体系结构 23。在提到“解码器架构”时，除非另有说明，否则主要是指现有文献中的因果解码器架构。

**前缀解码器体系结构**。前缀解码器架构（又名非因果解码器 [244]）修改了因果解码器的掩码机制，以允许对前缀标记 [245] 执行双向注意，仅对生成的标记执行单向注意。这样，就像编码器-解码器架构一样，前缀解码器可以对前缀序列进行双向编码，并逐个自动回归预测输出标记，其中在编码和解码过程中共享相同的参数。与其从头开始进行预训练，不如不断训练因果解码器，然后将它们转换为前缀解码器以加速收敛[29]，例如，U-PaLM [118]是从PaLM [56]派生而来的。基于前缀解码器的现有代表性LLM包括GLM130B[93]和U-PaLM[118]。

**专家的混合**。对于上述三种类型的架构，我们可以通过混合专家 （MoE） 扩展来进一步扩展它们，其中每个输入的神经网络权重子集被稀疏激活，例如 Switch Transformer [25] 和 GLaM [112]。其主要优点是，MoE是一种灵活的方法，可以在保持恒定计算成本的同时扩展模型参数[25]。研究表明，通过增加专家数量或总参数大小，可以观察到显著的性能提升[246]。尽管有这些优点，但由于路由操作的复杂性和硬切换性质，训练大型 MoE 模型可能会遇到不稳定问题。为了增强基于MoE的语言模型的训练稳定性，引入了一些技术，例如在路由模块中有选择地使用高精度张量或以较小的范围初始化模型[25]。最近，人们普遍猜测 GPT-4 是基于 MoE 架构开发的，但未经官方验证。

**新兴架构**。传统的 Transformer 架构通常存在二次计算复杂性。正因为如此，在训练和进行长输入推理时，效率已成为一个重要问题。为了提高效率，一些研究旨在设计用于语言建模的新架构，包括参数化状态空间模型（例如，S4 [247]、GSS [248] 和 H3 [249]）、长卷积（如 Hyena [250]）以及包含递归更新机制的类 Transformer 架构（例如，RWKV [251] 和 RetNet [252]）。这些新架构的主要优点是双重的。首先，这些模型可以像RNN一样递归生成输出，这意味着它们在解码过程中只需要引用单个先前状态。它使解码过程更加高效，因为它消除了像传统 Transformer 那样重新访问所有先前状态的需要。其次，这些模型能够像 Transformer 一样并行编码整个句子。这与传统的 RNN 形成鲜明对比，后者必须逐个标记地对句子进行编码。因此，它们可以通过并行扫描 [253， 254]、FFT [250， 251] 和 Chunkwise Recurrent [252] 等技术从 GPU 的并行性中受益。这些技术使具有这些新架构的模型能够以高度并行和高效的方式进行训练。

#### 4.2.2 详细配置

自 Transformer [22] 推出以来，已经提出了各种改进来增强其训练稳定性、性能和计算效率。在这一部分中，我们将讨论 Transformer 四个主要部分的相应配置，包括归一化、位置嵌入、激活函数以及注意力和偏置。为了使本调查更加独立，我们在表 6 中提供了这些配置的详细公式。
![图片](../images/2024/06/16/llm_survey/image14.png "表6")

**归一化方法**。训练不稳定性对于预训练 LLM 来说是一个具有挑战性的问题。为了缓解这个问题，归一化是一种广泛采用的策略，用于稳定神经网络的训练。在原版Transformer [22]中，使用了LayerNorm [256]。最近，人们提出了几种先进的归一化技术作为 LayerNorm 的替代方案，例如 RMSNorm 和 DeepNorm。

• LayerNorm。在早期的研究中，BatchNorm [265]是一种常用的归一化方法。然而，处理可变长度的序列数据和小批量数据是很困难的。因此，引入了 LayerNorm [256] 进行逐层归一化。具体而言，计算每层所有激活的均值和方差，以重新定位和重新缩放激活。

• RMSNorm。为了提高 LayerNorm （LN） 的训练速度，提出了 RMSNorm [257] 方法，即仅使用求和激活的均方根 （RMS） 而不是均值和方差来重新缩放激活。相关研究已经证明它在Transformer的训练速度和性能方面具有优势[266]。采用RMSNorm的代表性模型包括Gopher [64]和Chinchilla [34]。

• DeepNorm。DeepNorm是由Microsoft提出的[258]，用于稳定深度Transformer的训练。使用DeepNorm作为残余连接，Transformers可以扩展到1,000层[258]，显示出稳定性和良好性能的优势。它已被GLM-130B采用[93]。

**归一化位置**。除了归一化方法外，归一化位置在LLM中也起着至关重要的作用。归一化位置通常有三种选择，即, post-LN, pre-LN, and sandwich-LN。

• post-LN。后LN用于香草变压器[22]，它被放置在残余块之间。然而，现有研究发现，由于输出层附近的梯度较大，后LN变压器的训练往往不稳定[267]。因此，在现有的LLM中很少采用post-LN，除非与其他策略联合使用（例如，在GLM130B中将post-LN与pre-LN联合使用[93]）。

• pre-LN。与post-LN不同，pre-LN [268]在每个子层之前应用，并在最终预测之前放置一个额外的LN。与后LN相比，pre-LN的transformer在训练中更稳定。然而，其表现比post-LN变异型更差[269]。尽管性能下降，但由于训练稳定性，大多数 LLM 仍然采用 pre-LN。但是有一个例外，当训练模型超过100B参数时，发现GLM中的pre-LN不稳定。

• Sandwich-LN。Sandwich-LN [255] 在pre-LN 的基础上，在残余连接前增加了额外的 LN，以避免变压器层输出中的值爆炸问题。然而，已经发现Sandwich-LN有时无法稳定LLM的训练，并可能导致训练崩溃[93]。

**激活函数**。为了获得良好的性能，还需要在前馈网络中正确设置激活函数。在现有的LLM中，GeLU激活[270]被广泛使用。特别是在最新的LLM（例如PaLM和LaMDA）中，还使用了GLU激活的变体[262,271]，尤其是SwiGLU和GeGLU变体，它们在实践中通常具有更好的性能[266]。然而，与GeLU相比，它们在前馈网络中需要额外的参数（约50%）[272]。

**位置嵌入**。由于 Transformer 中的自注意力模块是排列等变的，因此采用位置嵌入 （PE） 来注入绝对或相对位置信息以建模序列。

• 绝对位置嵌入。在原版变压器[22]中，采用了绝对位置嵌入。在编码器和解码器的底部，绝对位置嵌入被添加到输入嵌入中。在vanilla Transformer[22]中提出了两种绝对位置嵌入的变体，即正弦和学习位置嵌入，后者通常用于现有的预训练语言模型。

• 相对位置嵌入。与绝对位置嵌入不同，相对位置嵌入是根据键和查询之间的偏移量生成的[273]。在Transformer-XL中引入了一种流行的相对PE变体[274,275]。修改了键和查询之间的注意力分数计算，以引入对应于相对位置的可学习嵌入。T5 [82] 进一步简化了相对位置 emebdding随后被Gopher采用[64]。具体来说，它将可学习的标量添加到注意力分数中，其中标量是根据查询位置和键之间的距离计算的。与绝对PE相比，具有相对位置嵌入的Transformers可以推广到比这些序列更长的序列进行训练，即外推[264]。

由于RoPE具有优异的性能和长期衰减特性，RoPE在最新的LLM中被广泛采用，例如PaLM [56]和LLaMA [57]。基于RoPE，xPos[277]进一步改进了Transformer的平移不变性和长度外推。在旋转角度矢量的每个维度上，xPos 都会添加一个特殊的指数衰减，当基数较大时，该衰减会越小。随着距离的增加，它可以缓解训练过程中的不稳定现象。

• ALiBi。ALiBi[264]提出了改进Transformer的外推。与相对位置嵌入类似，它根据键和查询之间的 25 个距离对注意力分数进行偏差，并进行惩罚。与T5 [82]等相对位置嵌入方法不同，ALiBi中的惩罚分数是预定义的，没有任何可训练的参数。[264]的实证结果表明，ALiBi在比训练序列更长的序列上具有更好的外推性能，而不是几种流行的位置嵌入方法，如正弦PE[22]、RoPE[263]和T5偏差[82]。此外，研究表明，ALiBi还可以提高BLOOM的训练稳定性[78]。

**注意力**。注意力机制是Transformer的关键组成部分。它允许序列中的标记相互交互并计算输入和输出序列的表示形式。

• Full attention。在原版Transformer[22]中，注意力机制是以成对的方式进行的，考虑了序列中所有标记对之间的关系。它采用缩放的点积注意力，其中隐藏状态被映射到查询、键和值中。此外，Transformer 使用多头注意力而不是单头注意力，在不同的头中投射具有不同投影的查询、键和值。将每个磁头的输出串联作为最终输出。

• Sparse attention。Full attention的一个关键挑战是二次计算复杂性，这在处理长序列时成为一种负担。因此，提出了各种高效的Transformer变体来降低注意力机制的计算复杂性[278,279]。例如，GPT3 [55] 采用了局部带状稀疏注意力（即分解注意力 [280]）。每个查询只能根据位置处理令牌的子集，而不是整个序列。

• 多查询/分组查询注意力。多查询注意力是指不同的磁头在键和值上共享相同的线性变换矩阵的注意变体[281]。它实现了更高的推理速度，而对模型质量的牺牲很小。具有多查询注意力的代表性模型包括 PaLM [56] 和 StarCoder [98]。为了在多查询注意力和多头注意力之间做出权衡，人们探索了分组查询注意力（GQA）[282]。在 GQA 中，磁头被分配到不同的组中，属于同一组的磁头将共享相同的变换矩阵。特别是，GQA已被在最近发布的LLaMA 2模型中采用并进行了实证测试[99]。

• FlashAttention。与大多数现有的近似注意力方法不同，FlashAttention[283]从IO感知的角度优化了GPU上注意力模块的速度和内存消耗。现代 GPU 上存在不同级别的内存，例如，具有快速 IO 的 SRAM 和具有相对较慢 IO 的 HBM。FlashAttention将输入组织成模块，并引入必要的重新计算，以更好地利用快速存储器SRAM。FlashAttention 在 CUDA 中作为融合内核实现，已集成到 PyTorch [197]、DeepSpeed [74] 和 Megatron-LM [75] 中。更新后的 FlashAttention-2 [284] 进一步优化了 GPU 线程块和变形的工作分区，与原来的 FlashAttention 相比，速度提高了约 2×。

• PagedAttention。据观察，当 LLM 部署在服务器上时，GPU 内存主要被缓存的注意力键和值张量（称为 KV 缓存）占用。主要原因是输入长度经常变化，导致碎片化和过度保留问题。受操作系统中经典分页技术的启发，PagedAttention被提出来提高已部署LLM的内存效率和吞吐量[285]。具体来说，PagedAttention 将每个序列划分为子序列，并将这些子序列的相应 KV 缓存分配到不连续的物理块中。分页技术提高了 GPU 利用率，并在并行采样中实现了高效的内存共享。

为了将所有这些讨论放在一起，我们总结了现有文献中关于详细配置的建议。为了更强的泛化和训练稳定性，建议选择pre RMSNorm进行层归一化，选择SwiGLU或GeGLU作为激活函数。此外，LN 可能不会在嵌入层后立即使用，这可能会导致性能下降。至于位置嵌入，RoPE 或 ALiBi 是更好的选择，因为它在长序列上表现更好。

#### 4.2.3 预训练任务

#### 4.2.4 长上下文建模

在实际应用中，对 LLM 的长上下文建模能力的需求越来越大，例如 PDF 处理和故事写作 [286]。许多闭源 LLM 为长文本处理提供专业支持。例如，OpenAI 发布了具有 128K 上下文窗口的 GPT-4 Turbo，而 Anthropic 发布了具有 200K 上下文窗口的 Claude 2.1。为了增强长上下文建模能力，通常有两个可行的方向，即缩放位置嵌入和适配上下文窗口。接下来，我们详细介绍这两个部分。

缩放位置嵌入。基于 Transformer 的 LLM 可以在最大训练长度内学习有效的位置嵌入。因此，当使 LLM 适应超出最大训练长度的语言任务时，有必要扩展到更大的位置索引。一些特定的位置嵌入已被证明具有一定程度的泛化能力，可以泛化到训练长度之外的文本，这被正式称为外推能力。包括 T5 偏差 [82]、ALiBi [264]、xPos [277] 甚至 NoPE [287]。然而，作为主流的位置嵌入方法之一，RoPE在实证研究中表现出有限的外推能力[240]。在下文中，我们将讨论几种可以将 RoPE 扩展到更长文本的方法。

• 直接模型微调。要使 LLM 适应长上下文窗口，一种简单的方法是直接微调具有所需长度的长文本上的模型。上下文扩展可以在多阶段方法中增加长度（例如，2K → 8K → 32K）进行安排。为了进行有效的扩展，它需要专门准备的长文本进行训练。特别是，最近的一些研究表明，在长上下文模型中，质量比训练文本的长度更重要[288]。然而，最近的一项研究强调，在为长文本调整LLM时，微调方法往往天生就很慢[240]。

• 位置插值。该方法在原始上下文窗口内缩小位置索引，以避免在预训练期间出现分布外旋转角度[240,289]。更具体地说，这种方法将所有位置索引乘以系数 L/L′ （L < L′），其中 L 和 L ′ 分别表示原始上下文窗口长度和目标上下文窗口长度。实验结果[240]表明，与上述直接模型微调方法相比，该方法可以有效且高效地扩展上下文窗口。然而，值得注意的是，在处理较短的文本时，这种技术可能会对模型的性能产生不利影响[240,290]。

• 位置截断。为了减轻分布外旋转角度带来的挑战，另一种实用方法是截断较长的相对位置以满足最大训练长度的要求。具体来说，ReRoPE和LeakyReRoPE [291]引入了一个预定义的窗口长度，该窗口长度小于最大训练长度。保留此预定义窗口内的位置索引，而窗口外的位置索引将被截断为预定义的窗口长度或插值以与最大训练长度对齐。这种策略可以保留局部位置关系并增强外推能力。但是，这种方法需要计算两次注意力矩阵，以适应额外的计算预算。

• base修改。LLM通常使用预设的最大训练长度进行训练，例如Llama 2中的4096 [99]。然而，RoPE某些维度的波长可能超过较长文本的训练长度[276]，因此语言模型在这些维度上没有经过足够的训练（即完整的旋转周期）。因此，当我们将LLM调整为较长的文本时，某些维度的旋转角度在训练阶段永远不会出现[292]。给定一个固定的旋转角度t·θi，较小的基θi允许更大的距离t，即能够对较长的文本进行建模[235,276,288]。根据公式 4 中的公式 θi = b −2（i−1）/d，可以通过增加基数值来实现降低基数。此外，减小基数还有助于重新调整训练长度以下所有维度的波长，而通常需要持续的预训练才能使LLM适应长上下文窗口[292]。最近的一项研究[292]对这两种碱基修正方法进行了实证比较，结果表明，减少碱基在训练长度之外显示出更好的外推27能力，而增加碱基在训练长度内表现更好。

• base截断。与base修改类似，base的截断也集中在处理波长超过训练长度的奇异维度上[293]。根据公式 5 中的定义 λi = 2π/θi，波长 λi 大的维度相应具有小基 θi。基于这一观察结果，该方法首先定义了一个base范围[a，c]。给定base范围，base值按以下方式修改：（1）当θi≥c时，保留该值，（2）当θi≤a时，该值设置为零，（3）<当θi<c时，该值被截断为固定的小值。通过base截断，可以在较大的位置指数下避免分布外旋转角度。然而，这种方法在长上下文任务中表现不佳[293]。

**调整上下文窗口**。由于基于 Transformer 的 LLM 具有有限的上下文窗口，因此它们无法直接集成或利用超过上下文窗口的长序列的全部信息。为了减轻这种局限性，已经提出了几种使 LLM 适应长上下文的方法，如下所述:

• 并行上下文窗口。受融合-不可解码器[294]的启发，并行上下文窗口方法[295,296]采用分而治之的策略来处理输入文本。特别是，它将输入文本分成多个段，每个段都使用共享位置嵌入进行独立编码。在生成阶段，对注意力掩码进行了修改，使后续token可以访问每个段中的先前token。然而，这种方法无法区分不同段的顺序，限制了模型在某些任务上的能力。

• Λ 形上下文窗口。之前的一些研究表明，LLM倾向于将更多的注意力权重分配给所有先前标记中的起始标记和最接近标记[297,298]，即所谓的“中间迷失”现象[299]。基于这一观察结果，LM-Infinite [300] 和 StreamingLLM [298] 建议采用“Λ 形”注意力掩码，该掩码有选择地保留每个查询可以处理的初始标记和最近的标记，然后丢弃超出此范围的任何标记。实验表明，该方法可以促进具有固定内存的超长文本生成[298]。然而，它可能很难对提示中的长程依赖性进行建模，因为它无法有效地利用来自丢弃标记的信息[298]。

• 外部存储器。研究表明，在Transformer [301]中，相对较小的标记子集可以有效地捕获大多数注意力模式，即topk注意力键可以很好地近似于原始的全注意力。因此，许多研究建议将过去的密钥存储在外部存储器中，并利用k-NN搜索方法来检索k个最相关的标记以进行生成[238,301,302]。对于解码器模型，它通常使用一个特定的层来访问这些前 k 个外部标记，同时在其余层中仍然采用正常的上下文窗口 [238， 302]。

除了基于vanilla Transformer的研究外，还有大量变形金刚变体，其效率attentions和其他高效架构，旨在减轻长文本建模的高计算成本。这些研究已在第 4.2.1 节和第 4.2.2 节中进行了广泛讨论。此外，上下文压缩和提示技术（例如，迭代推理[303]）也被证明是处理长文本任务的可行策略[303–306]，而无需模型适配。
