## 引言

OpenAI 发布了 Deep Research，这是一个浏览网页以总结内容并根据摘要回答问题的系统。该系统令人印象深刻，当我们第一次尝试时，它让我们大吃一惊。

博文中的主要结果之一是通用 AI 助手基准测试 （GAIA） 的性能有了很大的提高，我们最近也在玩这个基准测试，他们在 1 次射击中成功达到了接近 67% 的正确答案，在涉及多个推理和工具使用的特别具有挑战性的“3 级”问题上达到了 47.6%（请参阅下面的 GAIA 介绍）。

DeepResearch 由一个 LLM（可以从 OpenAI 提供的当前 LLM 列表中选择，4o、o1、o3 等）和一个内部“代理框架”组成，该框架指导 LLM 使用网络搜索等工具并逐步组织其作。

虽然强大的 LLM 现在可以免费以开源形式获得（例如，参见最近的 DeepSeek R1 模型），但 OpenAI 并没有透露太多关于 Deep Research 背后的代理框架的信息......

## GAIA 基准

GAIA 可以说是代理商最全面的基准。它的问题非常困难，并且触及了基于 LLM 的系统的许多挑战。下面是一个难题的示例：

```
2008 年画作《乌兹别克斯坦的刺绣》中展示的哪些水果是 1949 年 10 月远洋客轮早餐菜单的一部分，后来被用作电影《最后的航程》的浮动道具？以逗号分隔的列表形式给出项目，根据它们在画中的排列从 12 点钟位置开始按顺时针顺序排序。使用每个水果的复数形式。
```

您可以看到此问题涉及几个挑战：

* 以受限格式回答，
* 使用多模态功能（从图像中提取水果），
* 收集几条信息，其中一些取决于另一些：
  * 识别图片上的水果
  * 查找哪艘远洋客轮被用作“The Last Voyage”的浮动道具
  * 查找上述远洋客轮的 1949 年 10 月早餐菜单
* 以正确的顺序将解决问题的轨迹链接在一起。
  
解决这个问题需要高水平的规划能力和严格的执行力，这是 LLM 单独使用时难以的两个领域。

所以它是代理系统的优秀测试集！

在 GAIA 的公共排行榜上，GPT-4 在没有任何代理设置的情况下使用时，甚至没有达到验证集的 7%。另一方面，通过 Deep Research，OpenAI 在验证集上达到了 67.36% 的分数，因此要好一个数量级！（尽管我们不知道他们在私有测试集上的实际表现如何。

让我们看看我们是否可以使用开源工具做得更好！

## 建立开放的深度研究

### 使用 CodeAgent

我们将解决的传统 AI 代理系统的第一个改进是使用所谓的“代码代理”。正如 Wang et al. （2024） 所表明的那样，让代理在代码中表达其动作有几个优点，但最值得注意的是，代码是专门为表达复杂的动作序列而设计的。

考虑 Wang 等人给出的这个例子：

![image](https://github.com/user-attachments/assets/a87eb593-80af-455c-9c8b-624aa9a677e3)

这突出了使用代码的几个优点：

* 代码比 JSON 简洁得多。
* 需要运行 4 个并行流，每个流 5 个连续作？在 JSON 中，您需要生成 20 个 JSON blob，每个 blob 都在各自的步骤中;在 Code 中，它只是 1 个步骤。
* 平均而言，该论文表明，Code作需要的步骤比 JSON 少 30%，这相当于减少了生成的令牌。由于 LLM 调用通常是代理系统的尺寸成本，这意味着您的代理系统运行成本要低 ~30%。
* 代码支持重用公共库中的工具
* 在基准测试中表现更好，原因有二：
* 更直观的作表达方式
* LLM 在培训中广泛接触代码
我们在 agent_reasoning_benchmark 上的实验证实了上述优势。

## 结果

在我们的 24 小时+ 复制冲刺中，我们已经看到我们的代理在 GAIA 上的表现稳步提高！

我们很快就从之前具有开放框架的 SoTA（Magentic-One 的 46% 左右）上升到目前在验证集上的性能 55.15%。

性能的提升主要是由于让我们的代理在代码中编写他们的作！事实上，当切换到以 JSON 而不是代码编写作的标准代理时，相同设置的性能会立即下降到验证集的平均 33%。

然而，这只是一个开始，还有很多事情需要改进！我们的开放工具可以做得更好，smolagents 框架也可以调整，我们很乐意探索更好的开放模型的性能来支持代理。

我们欢迎社区加入我们的行列，这样我们就可以共同利用开放研究的力量来构建一个伟大的开源代理框架！它将允许任何人在家中使用他们最喜欢的模型，使用完全本地和自定义的方法运行类似 DeepResearch 的代理！
